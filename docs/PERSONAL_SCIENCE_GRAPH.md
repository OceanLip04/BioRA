# 个人版研究逻辑：一条主线，多棵结论树

## 0.11.0：按研究逻辑阅读，而非堆叠节点

主线从科学问题出发，依次展示主要结果。每个主线结果是一级结论／树根，下面可以有二级、三级及更深结论，原子实验是叶子。层级不限制为固定两层或三层；树之间允许真实跨树证据和共享结论，数据仍是有向无环图，不强制每个节点只有一个父节点。

```text
科学问题 → 主线结果 1 → 为什么继续研究 → 主线结果 2 → …
              │                              │
           二级结论 A  ←── 跨树证据 ──→  二级结论 B
              │                              │
           三级结论                        三级结论
              │                              │
          原子实验 1、2                    原子实验 3、4
```

图中树的分枝仅示意排布；真实证据箭头始终从原子实验指向下层结论、再逐级指向上层结论。**原子实验不允许直连主线结果**，本机领域校验会拒绝这种捷径。跨树证据也是有明确方向的支持／反驳，不是无方向的装饰。

两种逻辑必须分开：

- 研究推进：`ScientificQuestion.mainline` 有序引用真实 `claimID`；`question` 写本轮回答什么，`motivation` 写为什么先研究它／上一结果留下的缺口为什么引出它，`origin=reported/inferred` 区分明确记录与归纳重建。研究顺序不是证明关系，并行结果明确说并行，不编造递进因果。
- 证据论证：原子实验→下层结论、下层结论→上层结论的实际关系。每条线有 `explanation`（比较、观察如何支持或挑战这个目标）与 `limitations`（不能据此证明什么）。论证依据属于边：同一实验对不同结论的证据作用可以不同。

画布自动排列将主线固定在同一横排，结论／实验按真实证据路径排在对应结果下方；共享节点仅画一次，跨树证据保留，支持线可用点线识别跨树，反驳保持虚线。手动拖动位置仍保存；自动排列清除手动位置回到逻辑布局。可切换「仅看主线／展开结论树」，选根结论会强调多级证据分支，点节点看问题、承接理由、具体论证与边界。未关联节点留在独立区域，不造连线；计划实验依然不是观察证据。

自然阅读界面在画布之外新增「研究主线」，按编号展示每个结果的问题、承接理由、结论，逐层展开其论证树；跨树关系和共享内容在画布查看。科学问题的完整原子实验／结论／证据编辑清单默认折叠，提供「整理主线」和每条边的论证依据编辑。文献库默认显示「研究主线」，另有「详细阅读」「论证画布」；PDF 待审阅稿也先展示主线。

### 提示词和兼容边界

论文仍经研究类型单标签判断→详细阅读→主线／结论树 JSON；图谱输出新增 `mainline:[{claim_key,question,motivation,origin}]`，证据与结论关系新增 `explanation,limitations`。当前模型返回必须逐层通过完整 JSON 字段、引用、语言、页码、唯一性、无环、主线引用及禁止直连校验。推断的研究承接理由明确标注，不能只按图号／创建时间排列，更不能为了满足结构编造中间结果。综述按综合证据主题组织，不造原创实验。

Assistant 的 `science_question` 分支支持 `action=mainline` 排列已有结论；`science_evidence` 使用自己的解释／边界字段构建多级／跨树关系。缺少真实节点或用户判断时自然追问，不编造 ID 或自动“证明”。

旧科学问题、旧文献、旧草稿缺少主线／论证依据时按空值解码，全部原节点与关系保留，不自动推断主线、不写回重建数据库。旧文献可经 Assistant 重新分析生成新待审阅稿；自己的科学问题可用「整理主线」。已有原子实验直连的旧结论不能直接选为主线根，先建立真实上层结论及下层关系。

### 验证和只读预览

新增领域、PDF JSON 和模拟 Assistant 测试覆盖多级结论（含12级）、跨树共享证据、主线与证据分离、拒绝原子实验直连、拒绝未知／缺少字段、解释与语言校验、保存／旧格式兼容。模拟测试不证明真实模型的抽取质量。

2026-10-01 最终验收：118 项 XCTest 全部通过；0.11.0 / build 14 release 构建、Info.plist 和严格签名检查通过。独立只读预览实际确认了暖色纸感／macOS 原生主题切换、主线阅读、逐层展开、两棵不同深度的子树、跨树反驳、节点论证详情、⌘＋缩放和「仅看主线／展开结论树」。布局优先选择实际支持路径作为显示归属，按子树叶子跨度安排位置；归属不改变真实连边，也不代表证据强度。共享节点只绘一次。未用真实 API 或私人 PDF 验证模型抽取质量，手动主线编辑及位置持久化主要通过自动测试验证，不宣称所有拖动场景已人工验收。

`--preview-mainline` 启动只读虚构示例，内存加载，不读取／迁移数据库，不保存用户数据；`--native-theme` 可同时预览原生主题。这是用于验证新界面的独立预览，不代表已修复外接盘 SQLite 的加载问题。正常应用启动逻辑和真实工作区仍保持原样。

## 0.6–0.8 历史实现（由上述主线／结论树布局替代）

## 这次重新定义的核心

网页版以 ScientificQuestion、Claim、CompleteExperimentRun、AtomicExperimentRun 和关系边构成图谱；个人 Mac 版保留这个思路，但不依赖团队 Neo4j。0.5 的“问题下面排列卡片”不能表示多个原子实验汇向同一结论，因此 0.6 改为真正的节点与有向连线画布。

```text
科学问题
  ↑ 指向问题
结论 A ← 支持/反驳 ← 观察或假设 B ← 支持/反驳 ← 原子实验 1、2、3…
  ↑ 支持/反驳
结论 C ← 另一组原子实验…
```

箭头方向始终从原始检验/前提指向被支持或反驳的论断。多个原子实验可指向同一观察或结论；一个结论又能成为更高层结论的前提。这是多对多的证据图，不是强制的一棵树。

## “原子实验”的边界

原子实验是一次可独立解释的检验，例如一次独立重复、一个对照组比较或一项成像复核，不等同于 Protocol 的“加样、孵育”等操作步骤，也不等同于日历里已排定但尚未执行的实验。

- 待记录：可以先保存检验方案，但没有观察结果，不能作为支持/反驳连线的起点。
- 已记录结果：必须填写实际观察；必须关联本机实验，或写明可追溯的原始记录出处。记录日期、方法及所属实验可附带保存。
- 从原子实验到论断的线由用户选择“支持”或“反驳”。关联实验、填写结果和画一条线都不等于统计证明，更不自动意味着因果关系。

论断类型仍是论断、假设、观察、结论；自评确信度是用户的主观标注，不作为统计概率使用。结论之间的线同样只表示人工评价的支持或反驳。关系不能悬空、自连、重复或形成有向循环；删除节点时其连线一同清理。所有内容进入原有 SQLite 工作区和 JSON 备份，旧版科学问题缺少新字段时按空数组读取，不改写旧数据。

## Mac 交互

问题列表与图谱画布分开滚动，列表可隐藏以扩大画布。图谱支持缩放、双向滚动、点按节点看详情、拖动专用手柄并保存位置、在详情中用键盘可操作的方向按钮微调、自动重新排列。专用手柄避免普通点选意外改变图谱。左侧是研究问题，越往右是更底层的论断和原子实验；连线颜色区分支持与反驳。自动排列按论断关系的层级和连接目标聚类，并对大量同层节点分列，避免画布无限向下扩张。可点击节点后创建关系，也可在下方清单中用表单操作；画布节点是原生 SwiftUI 按钮，不能仅靠鼠标识别。

0.8 增加了独立的「专注图谱」、适合窗口缩放，以及悬停/点选节点时对相邻证据链的视觉强调。直接拖动节点卡片调整位置，拖动空白处平移画布，单击空白处关闭节点详情；双指捏合、⌘＋滚轮、⌘＋加减号或按钮可缩放。PDF 图谱草稿沿用同一画布，文献内容在保存前保持只读，保存后进入独立的文献阅读库。PDF 提取与人工审阅规则见 `docs/PERSONAL_PDF_GRAPH.md`。

Canvas 只画非交互的连接线，不负责节点点击或辅助功能；这是为了让键盘和 VoiceOver 仍可到达每个节点。助手只读讨论图谱，明确区分计划、记录的结果和用户推断，不能自动写入“已证明”。

## 下一阶段要做到真正优秀

目前是有出处、可审阅的研究脉络工具，不是自动科研结论引擎。后续最有价值的增量应按顺序进行：

1. 在原子实验中增加结构化对照、样本量、测量值与单位、Protocol 版本及原始数据文件引用；只在用户确认后关联，不从自由文本悄悄猜测。
2. 给每条结论展示“支持证据数 / 反驳证据数 / 未完成检验数”及出处完整度，但不把计数机械地换算成可信概率；统计分析需按具体实验设计另建模型。
3. 大图增加聚焦分支、搜索定位、折叠与概览小地图，避免数百节点时视觉噪声；保留全量清单及键盘导航。
4. 增加版本历史、图谱快照与导出。AI 可以提出待审阅的论断或缺失对照建议，但不能擅自改变证据状态或替用户画“证明”线。

网页版的团队文件浏览、图数据库、服务端实验运行和实时协作不在当前个人版范围。新 `--demo` 图谱中的观察数据全部是明确标识的虚构界面示例。
