# BioRA：Protocol → 实验 → 实测耗时 → 下一次排程

## 用户工作流

1. Protocol 编辑器为每个原子步骤填写原始分钟数，保留三层结构与循环。未知时间仍为 0，排程前必须补齐。
2. 阅读页 →「从此 Protocol 创建实验」：使用已确认版本，填写实验名、样品数、希望开始时间，预览逐步估计与校准情况。
3. 「步骤时间与实测校准」：设置这个版本各步骤的时间类型和基准，改变样品数预览未来时间。
4. 我的实验 →「记录耗时与观察」：记录实际样品数、每轮步骤的实际分钟、异常备注及是否参与校准。可填小数；留空不是 0，不能默认用计划时间填实际时间。
5. 标记实验完成，符合条件的记录自动参与以后的估计，不需要单独点击训练。

Assistant 也可以处理：“安排明天的实验，共12个样品”“这次加样用了18分钟，记录下来”“加样按样品数学习，基准4个样品10分钟，孵育保持固定”。先返回固定功能标签，再提取独立字段；缺样品数时自然追问，不默认猜1。模型提取的实测记录和校准修改先显示确认，再经本机校验保存。

## 时间类型

| 类型 | 语义 | 历史使用 |
| --- | --- | --- |
| fixed | 规定孵育、反应、离心等时长；默认值 | 不学习、不按样品数放大，遵循原方案；改变固定时长需创建新版本 |
| learnedBatch | 用户明确允许校准的一批操作时间，假设不随样品数线性变化 | 至少3次完整的已完成实验记录，合并样品数统计 |
| learnedSamples | 用户明确指定随样品数变化的操作，并填写基准分钟及其样品数 | 相同样品数至少3次；只在两个已验证样品数之间插值 |

学习预测操作耗时，不判断反应完成、实验有效或设备容量，不改变温度、浓度、规定科学条件和安全要求。批次模式不代表仪器可容纳任意样品数；设备容量模型不在本轮范围内。

## 估计规则

- 原始记录完整保存；时间估计按需计算，不覆盖实测。
- 只使用同一准确方案版本的已完成实验。计划、进行中、取消、无样品数和明确排除的记录不参与。
- 一个步骤有多轮循环时，所有对应轮次都记录且未排除才贡献一次独立实验观察；先取各轮中位数。多轮不是多次独立实验，不补零、不用暂停片段充当独立记录。
- 校准窗口为最近插入的最多120个同版本已完成实验，不删除更早记录。
- 典型时间为中位数；排程预留取中位数与经验80百分位的较大者，上取整至分钟。它是规划余量，不是统计置信区间、预测置信度或完成保证。
- 样品相关模式按样品数分组。每组至少3次独立实验；精确样品数优先，否则仅在两侧都有可靠组时分别对典型／预留时间线性插值。
- 不对历史曲线越界外推。数据不足或超出验证范围时，按“基准分钟×本次样品数÷基准样品数”换算并明确标为未验证。批次模式不足时保持批次基准。
- 原始耗时必须有限、大于0、最多7200分钟；样品数1–100000。估计超限拒绝，不静默裁剪。
- 异常记录可以保留并排除。没有自动删除离群值、猜测中断原因或让LLM改回归系数。

算法示例：4个样品的三次时间6、8、10分钟，典型8、预留10；12个样品为18、20、22，典型20、预留22。8个样品在两组之间插值，典型14、预留16。这不是实验操作建议。

## 历史和事务保护

校准是独立的“版本＋步骤”关联层，不将学习值写回旧方案的 duration_minutes。方案三层结构不变。新版本不自动继承旧版历史，即使标题／步骤ID相同，避免将改动后的设备或实验条件混成一种操作。跨版本转移需以后另做显式映射和审阅。

候选冻结计划样品数、逐步典型／预留分钟、来源、所用独立实验数，以及配置／有效记录依据的指纹。经典排程仍校验顺序、仪器、个人冲突、工作时间、连续／暂停、截止和过夜。校准依据或方案修订变化需重新生成；过了开始时间的未采用候选拒绝写入，不自动移动已审阅步骤。

已采用排程和历史时间快照不随学习改变。实际样品数可以修正原计划，计划样品数另行保留，但不会静默重新排程。重复采用保持幂等；表单保存检查并发变化，错误或只读状态不写数据库。

## 数据与交换

Experiment 新增可选 sampleCount、scheduledSampleCount、timingFingerprint，以及默认空的 stepTimings、durationEstimates。实测条目含 stepID、iteration、actualMinutes、includeInLearning、note、recordedAt；iteration 如1.1、2.1。日历暂停片段在实测表合成一次执行。

Workspace.stepTimingConfigurations 保存 versionID、stepID、mode、baselineMinutes、referenceSampleCount。SQLite和完整JSON备份同时保存配置和原始记录。旧实验样品数仍未知、记录为空，不猜成1或批量重写。

独立Protocol V3 JSON仅交换不可变方案，不携带个人实测／校准；转移学习历史请用完整工作区备份。没有模型训练、云上传、新服务或Docker依赖。

实现：PersonalCore/ProtocolTiming.swift、Planner.swift、Workspace.swift；界面／保存为 TimingViews.swift、ExperimentTimingEditor.swift、ExperimentTimingStore.swift；Assistant 的参数契约和分支同步更新。
